# RepMap

Interactive map showing US Congressional Representatives and Senators with district boundary overlays, ZIP code search, voting records, legislation tracking, accountability report cards, election countdown timers, a committee network graph, and historical redistricting comparison.

**RepMap is a frontend-only application deployed entirely on Vercel.** There is no live backend server. Representative data, districts, ZIP lookups, and elections are static JSON regenerated weekly by a GitHub Action; votes, legislation, and report cards are served by three small Vercel serverless functions that proxy GovTrack and Congress.gov. Django is retained only as the *data-generation tool* that produces the static files — it is never deployed or run as a web server in production.

> **AI Agent Notice:** The AI summarization features referenced in old commit history (Anthropic/Claude integrations, `ai.py`, `AISummary` models) were removed long ago and no longer exist in this codebase. Do not attempt to resurrect them.

---

## Why frontend-only

The project originally ran a two-server architecture: a Vite/React frontend on Vercel and a Django/DRF backend on Render's free tier. Render's free tier sleeps after 15 minutes of inactivity, so the first visitor after a lull waited 1–2 minutes for the backend to wake up — and the frontend hard-blocked rendering on a backend round-trip just to fetch the Mapbox token. Since the vast majority of the app's data (representatives, districts, ZIP lookup, elections) never needed a live server to begin with, the whole backend was collapsed into a static build step. See `roadmap.md` for the migration writeup.

| Layer | Technology | Version |
|---|---|---|
| **Frontend** | React + TypeScript + Vite | React 18, Vite 6.3, TS 5.6 |
| **Map** | Mapbox GL JS via `react-map-gl` | mapbox-gl 3.7, react-map-gl 7.1 |
| **Routing** | React Router | react-router-dom 7.16 |
| **State Management** | Zustand | 5.0 |
| **Visualization** | D3.js (committee network graph) | 7.9 |
| **PWA / Offline** | vite-plugin-pwa (Workbox) | 1.3 |
| **Serverless functions** | Vercel Node.js runtime (`@vercel/node`) | frontend/api/*.ts |
| **Static hosting + CDN** | Vercel | — |
| **Data generation (build-time only)** | Django management commands | Django 4.2, DRF 3.15 (not deployed) |
| **Data refresh automation** | GitHub Actions (weekly cron) | `.github/workflows/update-data.yml` |

There is no database, cache, task queue, or auth layer in production. Django's SQLite database exists only transiently inside the GitHub Action run that regenerates the static data.

**What used to be a live Django API is now build-time only.** The 20+ REST endpoints that once served representatives, districts, ZIP lookups, and elections have no runtime equivalent — that data ships as static files. Only the three externally-sourced, time-sensitive datasets (votes, legislation, computed report cards) still need a server-side hop, and that's now three stateless functions instead of a whole Django deployment.

## Static Data Pipeline

`backend/representatives/management/commands/export_static_data.py` is the bridge between the Django-managed dataset and the deployed site. It:

- Serializes all federal representatives (`level in {us_house, us_senate}`) to `representatives.json`, with committee assignments split into a separate `committees.json` so the initial payload stays small.
- Copies the ZIP lookup table, election dates, and per-state district GeoJSON into `frontend/public/data/`.
- **Validates before writing anything**, and fails the whole command (nothing is written) if validation fails:
  - Deterministic output (sorted, compact JSON) — a no-op re-run produces zero git diff.
  - House count in [430, 441], Senate count in [96, 100].
  - Every representative has a bioguide ID, valid coordinates, and a known party.
  - **Seat-transition dedup:** if two rows share the same `(state, level, term_end)` — which happens when the upstream `congress-legislators` source briefly lists both an outgoing and incoming member around a resignation or death — the row with the later `term_start` is kept and the stale one is dropped. If more than two rows remain per state after that, the command still hard-fails rather than guessing.

Run it locally with `python manage.py export_static_data` from `backend/`. See `.github/workflows/update-data.yml` for how it runs on a schedule.

## Serverless Functions

Three functions in `frontend/api/`, all validating their `bioguide`/`govtrack` query params before making any upstream call (the primary abuse/rate-limit shield, since Vercel's Hobby tier has no built-in per-IP quota):

| Function | Upstream | Auth | Cache |
|---|---|---|---|
| `votes.ts` | GovTrack `api/v2/vote_voter` | none | 6h success, no-store on failure |
| `legislation.ts` | Congress.gov `v3/member/.../sponsored-legislation` + `cosponsored-legislation` | `CONGRESS_API_KEY` | 12h success |
| `report-card.ts` | Both of the above, in parallel | `CONGRESS_API_KEY` for the bill data | 6h |

`report-card.ts` computes attendance %, effectiveness % (bills that became law), and bipartisanship % (cosponsored vs. total activity) — logic ported directly from the old `backend/representatives/services/report_card.py`.

`maxDuration: 20` is set per-function in `vercel.json` because GovTrack has been observed taking 15–20 seconds on some queries; the default 10s Hobby budget was silently dropping real data.

## Environment Variables

### Frontend (Vercel dashboard — Production + Preview)

| Variable | Required | Notes |
|---|---|---|
| `VITE_MAPBOX_TOKEN` | **Yes** | Baked into the JS bundle at build time. Restrict it to your domain + `*.vercel.app` at mapbox.com/account/access-tokens. |
| `CONGRESS_API_KEY` | For legislation/report-card | Server-side only — never prefix with `VITE_`. Get one free at api.congress.gov/sign-up. |

Local frontend dev reads these from `frontend/.env` (see `frontend/.env.example`).

### Backend tooling (`.env` in `backend/`, or exported before running commands)

| Variable | Required | Notes |
|---|---|---|
| `DJANGO_SECRET_KEY` | **Yes** | Any value works for local tooling use — Django refuses to start without one. |
| `DATABASE_URL` | No | Omit for SQLite (used in CI). Set to a Postgres URL if you want persistent local state. |
| `OPENSTATES_API_KEY` | No | Only needed if you run `sync_state_legislators` (state legislators are not currently exported/shipped). |

## Local Development

### Frontend (the app itself)

```bash
cd frontend
npm install
cp .env.example .env      # set VITE_MAPBOX_TOKEN
npm run dev                # http://localhost:5173
```

### Serverless functions

```bash
cd frontend
vercel dev                 # serves frontend/api/*.ts on :3000
```

`vite.config.ts`'s dev proxy forwards `/api/*` from the Vite dev server (:5173) to `vercel dev` (:3000), so run both together. Set `CONGRESS_API_KEY` in your shell or a `.env` that `vercel dev` picks up to test the legislation/report-card paths.

### Regenerating static data

```bash
cd backend
python -m venv venv && source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements/base.txt
python manage.py migrate
python manage.py sync_legislators
python manage.py export_static_data
```

This writes into `frontend/public/data/`. Commit the result. The district/ZIP GeoJSON commands (`build_district_data`, `build_state_district_data`, `build_historical_district_data`, `build_zip_data`, `build_national_state_districts`) only need to run again after redistricting or if you're bootstrapping from scratch — the committed files are otherwise reused as-is.

### Backend tests

```bash
cd backend
python manage.py test
```

## Deployment (Vercel)

The project deploys as a single Vercel project with Root Directory set to `frontend/`. On push to `main`:
1. `npm run build` (`tsc && vite build`) builds the static site.
2. The three functions in `frontend/api/` are detected and deployed as Node serverless functions.
3. `vercel.json` applies the CSP/cache headers and the SPA rewrite (`/embed`, deep links, etc.).

No backend deployment step exists or is needed. `.github/workflows/update-data.yml` is what keeps the static data fresh — see [Static Data Pipeline](#static-data-pipeline) above.

## What Was Removed in the Frontend-Only Migration

Google OAuth sign-in, watchlists, and in-app notifications were already non-functional in production before the migration (the sign-in button was commented out, there were 0 registered users, and the Celery task that would have populated notifications was never scheduled). The frontend code for all three was deleted outright.

**The corresponding backend code (`views_watchlist.py`, `views_notifications.py`, `views_auth.py`, `serializers_watchlist.py`, `serializers_notifications.py`, `tasks.py`, the `UserWatchlist`/`Notification`/`SyncStatus` models, and their tests) was deliberately left in place** rather than deleted — it costs nothing since the backend is never deployed as a live server, and it documents a feature that could be revived later (e.g. with a hosted auth provider + Neon instead of Django sessions). It is genuinely dead code from a runtime perspective; do not spend time debugging or extending it without first re-establishing why a backend server would need to exist again.

## Security

- **CSP, cache headers, SPA rewrites:** `frontend/vercel.json` (replaces the old `backend/repmap/middleware.py`, which never actually applied to the Vercel-hosted frontend in the two-server era — worth knowing if you're wondering why a CSP change now visibly affects the app when it didn't before).
- **Mapbox token:** baked into the public JS bundle (standard Mapbox practice) and restricted by URL at mapbox.com, not kept secret server-side.
- **Congress.gov key:** server-side only, in the three serverless functions — never sent to the browser.
- **Input validation:** `frontend/api/_lib/http.ts` validates `bioguide`/`govtrack` query params against strict regexes before any upstream call.
- **No user data, no auth, no cookies, no sessions** in the current architecture.

## Key Conventions

- **Bioguide ID format:** single uppercase letter + 6 digits (e.g., `L000001`), validated via regex both client- and function-side.
- **`external_ids.govtrack_id` is a number**, not a string, in the exported JSON — `types/index.ts` reflects this (`Record<string, string | number>`).
- **Cache TTLs:** votes/report-card = 6h, legislation = 12h (Vercel edge cache, via `Cache-Control: s-maxage`), data files = 5 min HTTP max-age + service-worker StaleWhileRevalidate.
- **`meta.json.schema_version`** is the escape hatch for future breaking changes to the static data shape.
- **State codes:** always 2-letter uppercase abbreviations.
